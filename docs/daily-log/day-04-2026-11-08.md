# Day 04 — 2026-11-08

**Goal:** Service layer for all public reads (`@Transactional` where needed), Bean Validation on request input, a `@RestControllerAdvice` returning JSON 404/400 errors, and 2–3 seeded test materials (no real PDF yet).

## Done
- **Service layer:** both public controllers only call services, and the services use `@Transactional(readOnly = true)`. No change was needed.
- **Exceptions:** added `exception/ResourceNotFoundException`, `dto/ApiError` (timestamp, status, error, message) and `exception/GlobalExceptionHandler`. It maps not-found to 404, unknown URLs (`NoResourceFoundException`) to 404, constraint failures (`HandlerMethodValidationException`) to 400, and bad types (`MethodArgumentTypeMismatchException`) to 400.
- `MaterialService.findById` now throws `ResourceNotFoundException` instead of `ResponseStatusException`.
- **Validation:** `@Min(1)` on `day` and `@Size` on `subjectSlug` and `topic`, as query-param constraints on `PublicMaterialController.list`. No `@Validated` on the controller (Spring 6.1+ validates annotated params itself).
- **Seed data:** `db/dev/R__dev_seed_materials.sql`, a repeatable migration loaded only by the dev profile through `spring.flyway.locations: classpath:db/migration,classpath:db/dev`. It inserts three materials (two published, one unpublished) and skips rows whose `object_key` already exists.
- `.vscode/launch.json` with a "Backend (dev)" config that passes `--spring.profiles.active=dev`.

## Issues and resolutions

### 1. App failed to start: "Failed to configure a DataSource: 'url' attribute is not specified"
- **Symptom:** the log said `No active profile set, falling back to 1 default profile: "default"`, then the datasource failure.
- **Root cause:** the app was started with VS Code's Run button, which does not pass a profile. The datasource settings exist only in `application-dev.yaml`.
- **Resolution:** created `.vscode/launch.json` at the project root (`Project_Sarav/.vscode/`) with a "Backend (dev)" config and ran from the Run and Debug panel. The `mvn spring-boot:run -Dspring-boot.run.profiles=dev` command also works.
- **Prevention / note:** the Run button above `main` ignores `launch.json`. Use the Run and Debug dropdown.

### 2. `application-dev.yaml` failed to parse (`expected <block end>, but found '<block mapping start>'`)
- **Symptom:** `mvn test` failed with a SnakeYAML error pointing at `flyway:` on line 12, and the dev profile did not load.
- **Root cause:** `flyway:` was indented 3 spaces, while its sibling `jpa:` uses 2.
- **Resolution:** changed that one line to 2 spaces so `flyway` sits level with `datasource` and `jpa`. After that `mvn test` showed `The following 1 profile is active: "dev"` and passed.
- **Prevention / note:** YAML indentation must be consistent. Use 2 spaces throughout and let the editor show whitespace.

### 3. `@NotBlank` on optional query params
- **Note:** `@NotBlank` rejects `null`, so it would make the optional `subjectSlug` and `topic` required. Used `@Size` and `@Min` (which accept null) on the params. `@NotBlank` is saved for a request-body DTO when an admin create-material endpoint is added.

### 4. Test data and the earlier 403 on missing ids
- **Decision:** seed data lives in a dev-only repeatable migration, not `data.sql` (which sits outside Flyway's history) and not a main migration (which would run in production).
- **Side effect:** with the handler in place, a missing material is answered by `GlobalExceptionHandler` as a JSON 404 and no longer forwards to `/error`, so the Day 3 403 problem is fixed at the source. `/error` stays permitted in `SecurityConfig`.

### 5. `mvn test` failed with "no POM in this directory"
- **Symptom:** `The goal you specified requires a project to execute but there is no POM in this directory (/Users/canteen/Documents/Project_Sarav)`.
- **Root cause:** ran from the project root. The `pom.xml` is in `backend/`.
- **Resolution:** `cd backend` first.
