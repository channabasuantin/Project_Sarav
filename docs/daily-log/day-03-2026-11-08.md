# Day 03 — 2026-11-08

**Goal:** Flyway V2 `materials` table, `Material` entity and repository with query methods, `GET /api/public/materials?subjectSlug=&day=&topic=` (published only) and `GET /api/public/materials/{id}`.

## Done
- `db/migration/V2__materials.sql`: `materials` table with `subject_id` FK to `subjects`, `day_number`, `topic`, `title`, `content_type`, `object_key`, `file_size_bytes`, `published` (default false) and `created_at`, plus an index on `(subject_id, day_number)`.
- `entity/Material` (lazy `@ManyToOne` to `Subject`), `repository/MaterialRepository`, `dto/MaterialResponse`, `service/MaterialService`, `controller/PublicMaterialController`.
- The list endpoint uses one `@Query` with optional filters (`:param is null or ...`) and `join fetch` on the subject, so only published rows are returned and there are no extra queries.
- `GET /{id}` uses `findByIdAndPublishedTrue` with an entity graph.
- `MaterialResponse` leaves out `object_key`, which is an internal storage path.
- Test rows were inserted with psql against the local database, not in the migration.

## Issues and resolutions

### 1. `curl` commands failed with "URL rejected" and "missing delimiter for 'u' glob qualifier"
- **Symptom:** `curl: (3) URL rejected: No host part in the URL`, `curl: (7) Failed to connect to 0.0.0.200 port 80`, and a zsh glob error.
- **Root cause:** the commands were pasted with trailing `# comments`. Interactive zsh passes those to curl as arguments. Unquoted URLs containing `?` are also treated as globs by zsh.
- **Resolution:** pasted the commands without comments and quoted every URL that has a query string.
- **Prevention / note:** always quote URLs with `?` or `&`.

### 2. Every `/api/public/materials` URL returned 403
- **Symptom:** the list and `/materials/{id}` returned `HTTP/1.1 403` with an empty body, although `/api/public/**` is permitted. `/api/public/subjects` still returned 200.
- **Root cause:** the Java code for materials had not been created or restarted into the running app. Only `V2__materials.sql` existed, and `target/classes` had no Material classes. With no matching route Spring raises a 404, and Spring Security then blocked the internal `/error` page, which turned it into a 403.
- **Resolution:** created the five Java files, saved them, stopped the app and restarted it with the dev profile.
- **Prevention / note:** a 403 on a permitted route often means an exception or a missing route, not an auth problem. Check the log and `target/classes`. There is no hot reload, so restart after every change.

### 3. `/materials/2` (unpublished) and `/materials/999` returned 403, not 404
- **Symptom:** after the code was in place, list, filters and `/materials/1` worked, but missing or unpublished ids returned 403.
- **Root cause:** the service throws `ResponseStatusException(NOT_FOUND)`. Spring forwards to `/error`, which `SecurityConfig` did not permit, so Security replaced the 404 with a 403.
- **Resolution:** added `/error` to the `permitAll()` matchers in `config/SecurityConfig.java`. Both ids now return 404.
- **Prevention / note:** unpublished and nonexistent materials give the same 404, so the API doesn't reveal that an unpublished row exists.

### 4. Test data and migrations
- **Question:** whether to paste the test `INSERT` into `V2__materials.sql`.
- **Decision:** no. A migration runs in every environment, and editing an applied migration causes a Flyway checksum mismatch. The rows were inserted with psql (`INSERT 0 2`) against the local database.
