## Issues and resolutions

### 1. Non-resolvable parent POM (`spring-boot-starter-parent:4.1.2`)
- **Symptom:** the IDE showed `Non-resolvable parent POM ... PKIX path building failed: unable to find valid certification path to requested target` on the `<parent>` line of `backend/pom.xml`.
- **Root cause:** Zscaler re-signs HTTPS traffic to Maven Central (`repo.maven.apache.org`), and the JVM doing the download didn't trust the Zscaler root CA. Maven also cached the failed download, so it didn't retry even after trust was sorted out.
- **Resolution:** ran `mvn -U` with JDK 25 to force a retry. JDK 25's cacerts already had a `zscaler-root` entry, and the parent POM downloaded into `~/.m2`. No project files or JDK settings were changed.
- **Prevention / note:** if the error persists in VS Code, run **Java: Clean Java Language Server Workspace** and make sure the Java extension's runtime is JDK 25.

### 2. Wrong JDK on `JAVA_HOME`
- **Symptom:** a plain `mvn` in a non-interactive shell used JDK 8 (`Java version: 1.8.0_381`), but the project needs Java 25.
- **Root cause:** `~/.zshenv` exports `JAVA_HOME` as the JDK 8 path. `~/.zshrc` overrides it with the JDK 25 path, but only interactive shells read `.zshrc`.
- **Resolution:** no change. Builds were run with an explicit `JAVA_HOME=/Users/canteen/Library/Java/JavaVirtualMachines/openjdk-25.0.2/Contents/Home`.
- **Prevention / note:** open decision on whether to change `.zshenv` or use a per-project setting. The vendor and approval status of this JDK 25 build has not been confirmed. JDK 8 and 11 on this machine are Oracle builds, so check Oracle licensing and Intuit approval before using them.

### 3. `contextLoads` failed: no DataSource
- **Symptom:** `Failed to configure a DataSource: 'url' attribute is not specified and no embedded datasource could be configured. Reason: Failed to determine a suitable driver class`.
- **Root cause:** the datasource settings live only in `application-dev.yaml`. `@SpringBootTest` ran with no active profile, so there was no JDBC URL.
- **Resolution:** added `@ActiveProfiles("dev")` to `backend/src/test/java/com/sankalpa/backend/BackendApplicationTests.java`.
- **Prevention / note:** the test now needs local Postgres running with the `sankalpa` database, so it fails on a machine or CI runner without it. Testcontainers would remove that dependency, but it needs a running Docker daemon, and Rancher Desktop was not running.
