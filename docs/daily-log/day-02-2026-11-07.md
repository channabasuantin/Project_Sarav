# Day 02 — 2026-11-07

**Goal:** Flyway V1 `subjects` table with seed data, `Subject` entity and repository, service, response DTO, and a public `GET /api/public/subjects` endpoint.

## Done
- `db/migration/V1__subjects.sql`: creates `subjects` (`id`, `name`, `slug` unique, `display_order`, `created_at`) and seeds 5 subjects (Polity, History, Geography, Economy, Environment).
- Package-by-layer structure under `com.sankalpa.backend`: `entity/Subject`, `repository/SubjectRepository`, `service/SubjectService`, `controller/PublicSubjectController`, `dto/SubjectResponse` (record), `config/SecurityConfig`.
- `SecurityConfig` permits `/api/public/**` and `/actuator/health`, requires authentication for everything else, and disables CSRF (stateless API).
- The service maps entities to `SubjectResponse`, so the entity is never exposed.

## Issues and resolutions

### 1. `GET /api/public/subjects` returned 401
- **Symptom:** `HTTP/1.1 401` with `WWW-Authenticate: Basic realm="Realm"` and a `JSESSIONID` cookie.
- **Root cause:** the Java files had not been created yet. With no `SecurityFilterChain`, Spring Security's default locks down every URL. There was also no controller, so the route would have been a 404 once security was open.
- **Resolution:** created the six classes and `SecurityConfig`, then restarted. The endpoint now returns 200.
- **Prevention / note:** Spring Security is on the classpath, so any new public route needs to match a `permitAll()` rule.

### 2. `The attribute readOnly is undefined for the annotation type Transactional`
- **Symptom:** a red error on `@Transactional(readOnly = true)` in `SubjectService`.
- **Root cause:** the import was `jakarta.transaction.Transactional`, which has no `readOnly` attribute. VS Code auto-import picked it.
- **Resolution:** changed it to `org.springframework.transaction.annotation.Transactional`.
- **Prevention / note:** in Spring services, always import Transactional from `org.springframework.transaction.annotation`.

### 3. `SecurityConfig.java` empty on disk
- **Symptom:** the editor showed 21 lines, but the file on disk was 0 bytes. Running the app would have repeated the 401.
- **Root cause:** the file was not saved.
- **Resolution:** saved the file (755 bytes), then restarted the app.
- **Prevention / note:** `mvn spring-boot:run` has no hot reload, so save everything and restart after each change.

### 4. Stray `entity/createdAt.java`
- **Symptom:** an empty class `createdAt` appeared next to `Subject`.
- **Root cause:** created by accident, probably by the editor's quick-fix on the `createdAt` field.
- **Resolution:** deleted the file.

### 5. Unauthenticated request returned 403, not 401
- **Symptom:** `GET /api/anything-else` returned 403, where 401 was expected.
- **Root cause:** `SecurityConfig` has no `httpBasic()` or login configured, so Spring Security has no 401 challenge to send and denies with 403. The route is still protected.
- **Resolution:** none needed for now.
- **Prevention / note:** add `.httpBasic(Customizer.withDefaults())` or a custom entry point when real authentication is built, if a 401 is wanted.
