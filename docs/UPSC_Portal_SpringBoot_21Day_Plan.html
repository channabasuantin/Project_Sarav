UPSC Notes Portal — 21-Day Plan (Spring Boot + React)

Stack: Spring Boot 3 (REST, JPA, Security, JWT) · React + Vite · PostgreSQL · Cloudflare R2 (PDFs) · Pages + Render/Neon deploy
Time: 2–3 hours/day (≈21 days). Full-time: ~10–12 days. Storage: 10 GB free on R2, 50 GB app cap.

Learning outcome: You build a real REST API (not Supabase), secure admin APIs, file upload to S3-compatible storage, and a React SPA for students + admin. Students never log in; PDFs are served from R2 URLs, not streamed through Tomcat.

Week 1 — Spring Boot foundation (Days 1–7)

DayTrackTasksDone when
1 Setup
  • Install JDK 17+ (OpenJDK), IntelliJ or VS Code, Docker Desktop, Git
  • Create GitHub repo Project_sankalpa; folders backend/, frontend/
  • docker-compose.yml: PostgreSQL 16, optional MinIO for local S3
  • Spring Initializr: Web, Validation, JPA, PostgreSQL, Flyway, Lombok (optional)
  • application-dev.yml → local DB; GET /actuator/health or /api/health
 App starts; health returns OK; Postgres connected
2 JPA
  • Flyway V1__subjects.sql — table + seed (Polity, History, …)
  • Entity Subject, SubjectRepository
  • SubjectService, PublicSubjectController → GET /api/public/subjects
  • Response DTOs (don’t expose entities directly)
 Postman/curl lists all subjects as JSON
3 JPA
  • Flyway V2__materials.sql — subject FK, day_number, topic, title, content_type, object_key, file_size_bytes, published
  • Entity Material, MaterialRepository with query methods
  • GET /api/public/materials?subjectSlug=&day=&topic= — only published=true
  • GET /api/public/materials/{id}
 Filter by subject slug works; unpublished hidden
4 Spring
  • Service layer for all public reads; @Transactional where needed
  • Bean Validation on DTOs (@NotBlank, @Min for day)
  • @RestControllerAdvice — 404, 400 JSON errors
  • Seed 2–3 test materials via Flyway or data.sql (no real PDF yet)
 Clean error JSON; layered architecture in place
5 Security
  • Add Spring Security; SecurityFilterChain: permit /api/public/**, /api/auth/login
  • Flyway V3__admin_user.sql — admin email + BCrypt hash (from env at first run or fixed seed)
  • AdminUser + UserDetailsService (single admin)
  • CSRF off for stateless API; CORS placeholder for localhost:5173
 Public GET works without token; admin routes return 401
6 JWT
  • JWT dependency; AuthController POST /api/auth/login → access token
  • JwtAuthenticationFilter before UsernamePasswordAuthenticationFilter
  • Secure /api/admin/** with hasRole("ADMIN")
  • Postman: login → use Bearer token on admin call
 Login returns JWT; admin endpoint succeeds with header
7 Admin API
  • AdminMaterialController: PATCH publish/unpublish, PUT metadata, DELETE
  • GET /api/admin/materials (includes unpublished)
  • Unit test 1–2 repository or service tests (JUnit 5)
 Full metadata CRUD without file upload yet

Week 2 — Files (Spring) + React student UI (Days 8–14)

DayTrackTasksDone when
8 Storage
  • StorageService interface: putObject, deleteObject, publicUrl
  • Dev: MinIO client (endpoint localhost); config via @ConfigurationProperties
  • Upload test file from a small @SpringBootTest or manual bean test
 File lands in MinIO; URL opens in browser
9 Upload
  • POST /api/admin/materials multipart: file + JSON (subjectId, day, topic, title, type)
  • Stream to MinIO; save Material with objectKey, fileSizeBytes, published=true
  • Return DTO with fileUrl for React
 Real PDF upload creates DB row + object in MinIO
10 Quota
  • StorageQuotaService — sum file sizes; reject if > 50 GB
  • GET /api/admin/storage-stats → usedBytes, capBytes, warn at 45 GB
  • Public material DTO includes fileUrl pointing to MinIO/R2, not Spring download
 Upload blocked when quota exceeded (test with low cap in dev)
11 R2
  • Cloudflare R2 bucket; API token; application-prod.yml S3Client → R2 endpoint
  • Same StorageService impl with profile switch MinIO vs R2
  • Upload one PDF to R2; verify public URL in Material response
 Prod storage config documented in docs/SETUP.md
12 React
  • npm create vite@latest frontend -- --template react-ts
  • React Router, axios, Tailwind (or CSS modules matching mockup)
  • .env VITE_API_BASE_URL=http://localhost:8080
  • Layout: header “Sankalpa UPSC”, mobile-first
 Dev server runs; can call backend health/subjects
13 React
  • Home page: subject tile grid from GET /api/public/subjects
  • Route /subjects/:slug — material cards from public materials API
  • Filters: day dropdown, content type; client or query params
 Matches student mockup (tiles + list)
14 React
  • Route /materials/:id/view — embed PDF.js with fileUrl from API
  • Download button → direct R2/MinIO URL
  • Loading + error states; empty subject message
 Student preview/download without admin UI

  • Deploy Spring Boot to Render/Fly.io; set env secrets
